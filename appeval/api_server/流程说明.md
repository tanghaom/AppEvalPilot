# 对方点击「开始评测」后，我这边怎么响应的整个过程

## 角色

- **对方**：他们的系统（例如 test-tool.deepwisdomai.com），用户在他们页面上点击「开始评测」。
- **我方**：你这台机器上跑的 API 服务（`python appeval/api_server/server.py --port 8888`）。

---

## 整体流程（按时间顺序）

```
对方系统                    我方 API 服务                    我方 Worker 进程
   |                              |                                |
   |  1. 用户点击「开始评测」        |                                |
   |  2. 对方后台请求我们的接口      |                                |
   |  ------------------------>   |                                |
   |     POST /start              |                                |
   |     { task_id, detail_id,     |  3. 收到请求，立即返回「接单成功」  |
   |       case_name, test_arry,   |  <-----------------------      |
   |       prod_url }              |     { code:0, success:true }   |
   |                              |                                |
   |                              |  4. 后台启动任务 _dispatch()     |
   |                              |  - 把状态记为 running            |
   |                              |  - 丢给进程池执行               |
   |                              |  -------------------------->   |
   |                              |                                |  5. 子进程里真正跑评测
   |                              |                                |     (开浏览器、访问 prod_url、
   |                              |                                |      执行 test_arry 里的用例)
   |                              |                                |
   |                              |  <-------------------------    |
   |                              |  6. 子进程返回 result            |
   |                              |  7. 状态改为 done，写入 result   |
   |                              |  8. 调用 _callback()             |
   |                              |                                |
   |  9. 我方请求对方的「结果回调」   |                                |
   |  <-----------------------   |  POST 对方 URL/detail/{id}       |
   |    对方收到评测结果 body        |  body = [ 一条结果记录 ]         |
   |    对方更新页面/状态           |                                |
```

---

## 分步说明

### 第 1～2 步：对方发起请求

- 用户在他们页面上点击「开始评测」。
- 对方后台会向**我们暴露的地址**发一个 HTTP 请求，例如：
  - **URL**：`http://我们机器IP:8888/start`
  - **方法**：`POST`
  - **Body（JSON）** 示例：
    ```json
    {
      "task_id": 1,
      "detail_id": 123,
      "case_name": "某用例名",
      "test_arry": ["打开页面并检查标题", "检查按钮可点击"],
      "prod_url": "https://要评测的网页或应用地址"
    }
    ```
- 也就是说：**对方点「开始评测」= 对方服务器调我们的 POST /start**。

---

### 第 3 步：我们「接单」并立刻返回

- 请求进到 `server.py` 的 `start_task()`。
- 我们先检查这个 `detail_id` 是否已经在跑（避免重复开任务）。
- 然后：
  - **马上**用 `asyncio.create_task(_dispatch(req))` 在**后台**启动评测任务；
  - **立刻**对对方返回 HTTP 响应，不等待评测跑完。
- 返回给对方的 body 大致是：
  ```json
  { "code": 0, "message": "ok", "data": { "success": true } }
  ```
- 所以对方点「开始评测」后，**立刻**拿到的只是「接单成功」，**不是**评测结果。

---

### 第 4～6 步：后台执行评测

- `_dispatch(req)` 在后台跑：
  1. 把 `_task_status[detail_id]` 设为 `{"status": "running", "case_name": ...}`。
  2. 用进程池（`ProcessPoolExecutor`）调 `_run_task_in_process(...)`，在**另一个进程**里执行，不阻塞 API。
  3. 子进程里会：
     - 起虚拟显示（Xvfb）、浏览器；
     - 访问 `prod_url`；
     - 按 `test_arry` 里的一条条用例做操作和判定（我们现有的 run_test 那一套）；
     - 把结果汇总成一个 `result` 字典。
  4. 子进程结束后，`_dispatch` 拿到 `result`，把状态改为 `"done"`，并把 `result` 存进 `_task_status[detail_id]`。

所以：**评测是在我们机器上、在后台进程里跑完的**，对方在「点开始」时已经拿到 200 并关闭连接了，不会一直等。

---

### 第 7～8 步：我们主动「回调」对方

- 任务一结束（无论成功还是异常），都会调用 `_callback(detail_id, result)`。
- `_callback` 做的事：
  - 拼 URL：`CALLBACK_BASE_URL` + `"/" + detail_id`  
    默认是：`https://test-tool.deepwisdomai.com/api/v1/agent-eval/notice/detail/123`
  - 用 **POST** 请求这个 URL，body 是一个数组，里面**一条**结果对象，例如：
    ```json
    [{
      "detail_id": "123",
      "case_name": "某用例名",
      "eval_cost": "120s",
      "version": "gemini-3-flash-preview",
      "test_cases": [
        { "test_id": "0", "case_desc": "打开页面并检查标题", "result": true, "evidence": "...", "cost": "" },
        { "test_id": "1", "case_desc": "检查按钮可点击", "result": false, "evidence": "...", "cost": "" }
      ]
    }]
    ```
- 也就是说：**任务结束后，「返回信息」是我们主动 POST 到对方接口的**，不是通过当初的 POST /start 的响应返回的。

---

### 第 9 步：对方收到结果

- 对方的接口（例如 `.../notice/detail/123`）收到我们这次 POST 后，会：
  - 根据 `detail_id` 找到对应评测单；
  - 把 body 里的结果存下来、更新状态；
  - 前端可以轮询或推送，显示「评测完成」和具体通过/不通过。

所以：**对方点击「开始评测」后，能看到的「返回信息」= 他们自己的接口收到我们回调 POST 的那份 body**。

---

## 小结（对应你的疑问）

| 你的疑问 | 对应事实 |
|----------|----------|
| 对方点「开始评测」我们怎么响应？ | 对方调我们的 **POST /start**；我们**立刻**返回「接单成功」，同时在**后台**开始跑评测。 |
| 评测在哪跑？ | 在我们机器上的**子进程**里跑（浏览器 + 用例执行），不阻塞 /start 的响应。 |
| 「返回信息」在哪？ | 任务结束后，我们**主动 POST** 到对方的回调 URL（`.../notice/detail/{detail_id}`），body 里是评测结果；对方是在**那个接口**收到返回信息的。 |
| 我们怎么知道任务结束了？ | 子进程返回后，我们把 `_task_status[detail_id]` 设为 `done` 并写入 `result`；你查 **GET /status** 或 **GET /status/{detail_id}** 就能看到这份结果。 |

---

## 上线方式（推荐）

按你说的方式来做即可：

1. **我们服务器上**：固定跑 API 服务，监听 8888（或先不用 Nginx 时直接对外 8888）。
   ```bash
   python appeval/api_server/server.py --port 8888
   # 若对方提供不同的回调地址：
   # python appeval/api_server/server.py --port 8888 --callback-url https://对方提供的回调根地址
   ```

2. **可选：前面加 Nginx**  
   用 Nginx 反代到本机 8888，对外用 80/443（或带域名），例如：
   - 对方访问：`https://eval.你们域名.com/start` → Nginx 转发到 `http://127.0.0.1:8888/start`。

3. **发给对方的信息**  
   把**对外的那个地址**发给对方，让他们请求这个地址的 `/start`：
   - 直连 8888：`http://我们服务器公网IP:8888`
   - 用 Nginx + 域名：`https://eval.你们域名.com`（或你们提供的 IP/域名 + 端口）

对方配置成：**开始评测时 POST 到 `{我们提供的地址}/start`**，即可按当前流程跑通。

## 本地测试不回调

本地自测时不需要把结果 POST 到对方，可关闭回调，避免外网请求失败刷屏：

- **方式一**：在 `config.yaml` 中设置 `skip_callback: true`（当前默认已开）。
- **方式二**：启动时加参数 `--no-callback`，例如：
  ```bash
  python appeval/api_server/server.py --port 8888 --no-callback
  ```

关闭后，任务完成时只会打印 `[Callback] detail_id=xxx 已跳过（本地测试，不回调对方）`，结果仍会写入内存（GET /status）和 `appeval/api_log`。上线对接对方时，把 `skip_callback` 改为 `false` 或去掉 `--no-callback` 即可恢复回调。
